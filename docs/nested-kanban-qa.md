# QA: сквозные сценарии двухуровневого канбана

Дата проверки: 2026-09-22. Проверялся текущий worktree после интеграции модели/API и renderer.

## Результат

Функциональных дефектов в проверенном объёме не обнаружено. Продуктовый код не изменялся: существующие
регрессионные тесты уже покрывают основной контракт, поэтому добавление дублирующих тестов не потребовалось.

Проверки выполнены:

- `pnpm typecheck` — успешно (core, CLI, desktop renderer/main).
- `pnpm test` вне sandbox — успешно: core `72/72`, CLI `5/5`, всего `77/77`.
- `packages/core/src/global-tasks.test.ts` — создание двух глобальных задач, независимое перемещение,
  изоляция подзадач и зависимостей, прогресс/счётчики, сохранение, миграция, удаление, ручное закрытие,
  `run_done`, повторный запуск без дублей и сценарии `runs finish`.
- `packages/core/src/coordinator-close.test.ts` — закрытие по последнему `run_done` после переоткрытия.
- `packages/core/src/prompts.test.ts` — инструкции повторного запуска и список существующих подзадач.
- `packages/cli/test/cli.test.js` — старые `task create`, `done`, `runs finish`, а также `global list/get/tasks/
  add-task/move/delete` и приоритет явного `--global`.

## Проверка UI-интеграции

По реализации renderer прослежены следующие сценарии:

- Верхняя доска группирует глобальные карточки по реальным `Project.columns`, показывает счётчики колонок,
  статус, описание, прогресс `done/total`, активность, вопросы и ревью; drag вызывает `globalTasks.move`.
- Открытие карточки устанавливает `ProjectView.globalId`; внутренняя доска получает только задачи с
  `task.runId === global.id`, а создание подзадачи идёт через `globalTasks.createTask`.
- Возврат восстанавливает фокус на исходной карточке; `Enter`/`Space` открывают её, `Escape` возвращает
  на общую доску вне полей и модалок.
- `globalId` и вкладка сохраняются в `localStorage` с ключом проекта; при смене проекта состояние выбранной
  задачи не смешивается с активным проектом.
- Вопросы считаются только открытые и привязываются через `taskId -> runId`; review считается по kind
  колонки. В открытой глобальной задаче `Board` получает прежние действия подзадач: вопросы, review,
  запуск воркера и терминал.
- Запуск на карточке вызывает `globalTasks.startCoordinator`, запрещён для «Входящих» и живого координатора;
  живость определяется терминалом с `role: coordinator` и тем же `runId`, что предотвращает UI-дубли.
- Пустые колонки и отсутствие подзадач имеют отдельные состояния. Общая доска и внутренняя доска имеют
  вертикальный скролл колонок/контента, длинные описания ограничиваются и раскрываются, текст переносится.
  Терминалы сохраняются в реестре, получают tail после перезагрузки и имеют состояние пустого списка.

## Ограничения

- Реальную Electron UI-проверку не выполнял: рабочее приложение не перезапускал, как требовалось в задаче;
  проверка UI была статической трассировкой связей и обработчиков исходного renderer.
- Первый запуск `pnpm test` внутри sandbox завис на CLI fixture: создание Unix-сокета запрещено (`listen
  EPERM`). Повторный запуск вне sandbox прошёл полностью; это ограничение тестовой среды, не дефект CLI.
- Не проверялись реальные внешние агентские процессы/PTY и визуальное соответствие макету на экране.
