# Прогресс графа на экране глобальной задачи — макеты

Задача: показать граф типа задачи только для чтения, текущую ноду (`stage.nodeId`, заход `stage.visits`) и пройденный
путь (`stageHistory`: `from`, `outcome`, `visit`). Новых полей и API нет — всё берётся из снимка `GlobalTask`
(`packages/core/src/global-tasks.ts`: `stage`, `stageHistory`, `workflowScope`) и графа прогона.

Сейчас позиция видна только чипом «Этап: Реализация · 2-й заход» (`GlobalTaskHeader.tsx`, `runStage.ts`),
лентой «История» (`GlobalHistory.tsx`, `globalTimeline.ts`) и пилюлей пути подзадачи (`SubtaskPathBlock.tsx`, `subtaskPath.ts`).

Макеты статичные, открываются в браузере без сборки. Сверху — переключатели: состояние задачи (1-й заход «Реализации»,
возврат после reject — 2-й заход, «Проверка человеком», «Сделано»), ширина окна (1280 / 860) и тема. Их можно задать в
адресе: `?state=ret&w=narrow&theme=light`. Данные — граф типа «Фронтенд и бэкенд»: Старт → Анализ → Реализация → Ревью
(принять → Проверка человеком, вернуть → Реализация) → Проверка человеком (принять → Конец, вернуть → Реализация).

Общие обозначения графа во всех вариантах: пройденная нода — бирюзовая рамка и галочка, текущая — акцентная рамка
с пульсом и плашкой «сейчас · 2-й заход» (красной, если в ноду вернули), будущая — пунктир. Пройденные переходы —
сплошные и толще, непройденные — бледный пунктир. На возврате — счётчик «×1», на ноде с несколькими заходами — «×2».

## Вариант A — вкладка «Граф» (`variant-a.html`)

Новая вкладка между «Доской» и «Итогом»: крупный граф и справа панель выбранной ноды (по умолчанию текущей) — заходы
с временем, причина возврата цитатой, сводка сданного этапа, подзадачи захода с пилюлей пути. «Открыть путь подзадачи»
проваливается внутрь «Реализации» (хлебные крошки, как в редакторе): путь Работа → Мерж → Конец с конфликтом, на нодах —
метки подзадач.

- **Чип этапа** остаётся и становится ссылкой на вкладку «Граф».
- **История** не меняется, у строк переходов этапов — ссылка «на графе».
- **Возврат (visit 2)**: красная плашка «сейчас · 2-й заход» на «Реализации», сплошной красный возврат «×1» от «Ревью»,
  в панели 2-й заход помечен «вернул Ревью» с причиной.

Плюсы: полный граф и полные сведения о каждой ноде; проще всего сделать — отдельная вкладка ничего не двигает на других;
переиспользуются геометрия и стили холста редактора (`WorkflowCanvas`, `wf-node-*`).
Минусы: граф спрятан за вкладкой, пока туда не перейдёшь — видишь только чип; дублирует часть «Истории» (заходы).

## Вариант B — граф над историей, «Ход работы» (`variant-b.html`)

Вкладка «История» становится «Ходом работы»: сверху компактный граф (закреплён при прокрутке), ниже лента, сгруппированная
по заходам в этапы — карточки «Реализация · 2-й заход ↩ вернул Ревью» с причиной, подзадачами захода и их путём, сводкой
сдачи. Последний заход раскрыт, вверху — «Впереди: Проверка человеком». Клик по ноде оставляет в ленте только её заходы.

- **Чип этапа** остаётся (нужен на «Доске») и ведёт в «Ход работы».
- **История** перестраивается: вместо плоской ленты по дням — заходы в этапы; события внутри захода.
- **Возврат**: отдельная карточка «Ревью» (красная точка — ушла с возвратом) и новая карточка «Реализация · 2-й заход».

Плюсы: граф и история связаны — видно не только «где», но и «почему так»; нет новой вкладки.
Минусы: самая большая переделка `globalTimeline.ts` (группировка по `stageHistory`); события вне этапов (правка цели,
координатор) надо куда-то пристроить; компактный граф на узком окне мелкий.

## Вариант C — полоса этапов в шапке (`variant-c.html`)

Чип «Этап: …» заменяет полоса этапов основного пути (Анализ → Реализация → Ревью → Проверка → Сделано) прямо в шапке —
видна на любой вкладке. Пройденный этап — галочка и время, текущий — «сейчас · 2-й заход», возвраты — красный счётчик
«↩ 1» на этапе, куда вернули. Кнопка «Граф» раскрывает под шапкой панель: полный граф и справа, если текущий этап —
«Работа», путь подзадачи и подзадачи захода (иначе — заходы текущей ноды и что будет при решении).

- **Чип этапа** убирается — его роль берёт полоса.
- **История** не меняется, строки возвратов подсвечены фоном.
- **Возврат**: «↩ 1» на «Реализации», подпись «сейчас · 2-й заход»; в раскрытом графе — красная дуга «×1».

Плюсы: позиция видна всегда и читается за секунду; полный граф — в один клик без смены вкладки.
Минусы: полоса линеаризует граф — ветвящиеся графы (`decision`, `condition`) в полосу ложатся плохо, нужно правило
«основной путь = пройденный + next/accept до конца»; шапка становится выше на строку; раскрытая панель отъедает высоту у доски.

## Рекомендация

**C** — как основной вид, с полным графом по кнопке. Главная боль — «где сейчас задача» не видно без чтения чипа
и ленты; C решает её на всех вкладках и не заставляет переделывать «Историю». Панель графа из C — тот же компонент,
что и в A: если понадобится подробная панель ноды, её можно вырастить из раскрытого вида.
Если в типах задач уже много ветвящихся графов (`decision`) — брать **A**: он показывает любой граф без линеаризации.

## Открыто для решения

- Для C: как строить полосу у ветвящегося графа — по фактически пройденному пути плюс ветка `accept`/`next` вперёд,
  или показывать в полосе только пройденное и текущее.
- Помнить ли раскрытие панели графа между задачами (localStorage) или открывать свёрнутой.
- Нужна ли в проваливании внутрь «Работы» (A, C) отметка подзадач на нодах пути или достаточно пилюль.
