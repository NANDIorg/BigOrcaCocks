# Окно «Документы» со всеми файлами проекта — макеты

> Исторический материал: описание и результаты ниже относятся к моменту создания
> документа, а не к текущему состоянию приложения. Актуальное устройство —
> [общий фундамент](../../shared-foundation.md), проверки —
> [журнал готовности](../../orca-foundation-progress.md).

Цель: «Перенести файлы в документы, чтобы в документах были все файлы проекта, и можно было читать и смотреть все файлы».
Вкладка «Файлы» уходит, окно «Документы» (кнопка в левой панели) становится единственным входом. План и ограничения —
в ответе аналитика (задача `task_mupawmnj5`): плоский индекс из `git ls-files`, просмотр текста / картинок / HTML / PDF,
заглушки для всего, что показывать нельзя. Здесь — **только макеты**, продуктовый код не менялся.

Три варианта — `variant-1.html`, `variant-2.html`, `variant-3.html`. Каждый — один самодостаточный файл (стили и скрипт внутри,
без сети и без сборки), живой: клики, ввод, клавиши работают, данные выдуманы.

## Как смотреть

Сверху — панель макета (в приложение не переносится): **Вход** · **Дерево** · **Просмотр** · **Заглушки** · **Ошибки**, ширина окна
(**Широкое** 1480 · **Среднее** 1040 · **Минимум 860** → окно 812), опция **«Подсветка»**. Под ней — строка «что смотреть в этом состоянии».
Состояние и ширину можно задать адресом: `variant-1.html?w=812#md`.

| Группа | Состояния |
|---|---|
| Вход | как открыть окно: вкладки Канбан / Терминалы / Статистика / О проекте, вкладки «Файлы» нет, кнопка «Документы» |
| Дерево | дерево со смешанными типами; поиск ⌘P (выдача + «ещё N»); «Недавние»; баннер «список обрезан» |
| Просмотр | код; код + ⌘F; markdown (оглавление, относительная картинка, ссылка на `.ts`); картинка; HTML (Код ⇄ Превью) |
| Заглушки | бинарный; текст > 1 МиБ; картинка > 10 МиБ; PDF; не UTF-8; симлинк наружу; `.env` скрыт (альтернатива решению 1) |
| Ошибки | «файл не найден» (прежний документ остаётся); «приложение устарело — перезапустите» |

Клик по любому файлу в дереве открывает его просмотр (содержимое в макете — образец для типа файла). Работают: ⌘P / ⌘F, ↑ ↓ Enter Esc,
‹ › (история), закрытие ошибки, «Документ ⇄ Исходник», ссылка из markdown на `shared/ipc.ts` (открывается в том же окне),
ссылка на несуществующий «старый план» (даёт «файл не найден»).

## Что одинаково во всех вариантах

Это то, что можно решать один раз, независимо от выбранной раскладки.

- **Токены и классы.** Цвета — тема graphite из `shared/theme.ts`; существующие блоки `docs-*` (`docs-row`, `docs-hit`, `docs-crumbs`, `docs-find`, `docs-err`, `docs-blank`, …),
  `.doc-md` из `docs-markdown.css`. Новое: `docs-code` (код с номерами), `docs-status`, `docs-html`, `docs-img`, заглушки на базе `docs-blank`, `docs-trunc` (баннер),
  `docs-more` («ещё N»), сегментный переключатель `seg2`, меню `popup-menu`. Брейкпоинты те же, что в приложении сейчас: оглавление/правая колонка прячутся при ≤ 1100 px окна, дерево ужимается до 230 px при ≤ 820 px.
- **Дерево.** Папки сверху, цепочка из одной папки схлопывается (`apps/desktop`), счётчики файлов, **иконки по виду файла** (md, код, конфиг, текст, html, картинка, pdf, бинарный, `.env`) —
  в вариантах 1 и 2 цветные из токенов темы, в варианте 3 монограммы расширения (TS, MD, YML, `{ }`). **Симлинк** — значок цепочки у имени, **симлинк наружу** — красный значок и приглушённое имя.
  Точечные файлы (`.env`, `.gitignore`, `.github/…`) лежат в общем списке. Метки «новый / изменён» и время — как сейчас.
- **Поиск ⌘P** — по пути всего проекта; выдача ограничена (в макете 8 строк, в приложении 100), дальше строка «Ещё N совпадений — уточните запрос»; ниже — совпадения в тексте открытого файла.
  **«Недавние»** — плоский список по времени, любые типы, не больше 200 (подпись про лимит). **«Список обрезан»** — янтарный баннер: в проекте больше 100 000 файлов, показаны первые 100 000, счётчик «100 000+».
- **Код.** Моноширинный 13 px / 1.6, без переноса строк, колонка номеров (липкая слева, не выделяется), полоса ⌘F (`1 из 5`, ↑ ↓, Enter / Shift+Enter, Esc), строка статуса: тип, кодировка, строк, размер, время.
  **Подсветки синтаксиса в v1 нет**; в макете она — опция (переключатель «Подсветка» в панели; в варианте 3 ещё и в строке статуса), чтобы человек увидел, как это выглядит, и решил про новую зависимость (T6).
- **Markdown** — как сейчас (типографика, оглавление, плашка «также изменён в задаче…»), плюс относительная картинка из проекта, ссылки на любые файлы проекта (маркер `▤` — документ, `‹›` — код), переключатель «Документ ⇄ Исходник».
- **Картинка** — «Вписать» (по умолчанию) / «100 %», шахматный фон под прозрачность; SVG показывается как картинка.
- **HTML** — «Код» по умолчанию, «Превью» — изолированный фрейм без сети; над фреймом баннер «Изолированная страница, сеть отключена. Не загружено: fonts.googleapis.com — 1 запрос заблокирован. Файлы с точкой в пути странице недоступны»,
  в строке статуса «изолировано, без сети». Переключателя «Интернет-ресурсы», как в показе, **нет и не будет** (план аналитика: для живого корня проекта сеть не выдаётся никогда).
- **Заглушки** — это обычный результат, а не ошибка: значок, заголовок, причина, чипы (тип, размер, время), действия. «Открыть» есть **только** у белого списка (картинки, md, html, pdf); у остальных вместо кнопки пояснение
  «приложение не запускает чужие файлы из репозитория». «Показать в Finder» и «Копировать путь» — у всех.
- **Ошибки.** «Файл не найден» — баннер `docs-err` над прежним документом (как сейчас) с «Обновить список». «Приложение устарело» — сообщение вместо просмотра, а дерево и markdown работают на старом `docs:list` (только `.md`, счётчики пересчитаны).
- **Доступность.** Контраст замерен: `muted` на `frame` / `page` / `side` 6,5 / 7,1 / 6,1:1; номера строк 5,2:1; цветные чипы 6,9–9,3:1; токены подсветки 5,0–9,7:1; значки ≥ 3,7:1. У всех кнопок без текста `aria-label` и `title`;
  переключатели — `aria-pressed`; дерево — `role="tree"` / `treeitem` / `aria-expanded`; выдача — `listbox` / `option`; баннеры — `role="alert"` / `status`; фокус — кольцо 2 px `--accent`; анимации выключаются при `prefers-reduced-motion`.
- **Вкладки «Файлы» нет.** Состояние «Вход»: единственный вход — кнопка «Документы» в левой панели; сохранённая вкладка `files` откроет «Канбан».

## Чем варианты отличаются

### Вариант 1 — «Проводник»: дерево | одна панель | правая колонка только у markdown
Самая близкая к текущему окну раскладка. Над документом одна строка: ‹ › · крошки · переключатель вида (Документ ⇄ Исходник / Код ⇄ Превью / Вписать ⇄ 100 %) · поиск в файле · оглавление · копировать путь · показать в Finder · открыть.
Правая колонка (оглавление) **есть только у markdown**, у кода, картинок и HTML она скрыта и просмотр занимает всю ширину; сведения о файле — в строке статуса внизу. На узком окне действия уходят в меню «⋯», оглавление — во всплывающую панель.
Открытый файл один, возврат — историей ‹ ›.

**Плюсы:** меньше всего нового (поверх `DocsModal` добавляются панель вида, строка статуса и четыре просмотрщика); самая широкая область под код после варианта 3; один способ навигации — привычный.
**Минусы:** между двумя файлами нельзя переключиться без дерева или истории; при переходе markdown → код правая колонка исчезает и текст «прыгает» на 230 px; действия — иконки без подписей (подписи в `title`).

### Вариант 2 — вкладки открытых файлов и инспектор «Сведения»
Над документом полоса вкладок: клик в дереве открывает **временную** вкладку (курсив — её заменит следующий клик), двойной клик закрепляет, × закрывает. Справа **всегда** колонка «Сведения»: значок и тип, оглавление (у markdown),
факты (тип, кодировка, строк, размер, изменён), путь, **подписанные кнопки** «Копировать путь» / «Показать в Finder» / «Открыть в системе», для HTML — блок «Изоляция», для файла из задач — «Также в задаче». Строки статуса на широком окне нет.
Меньше 1100 px инспектор прячется: факты уезжают в строку статуса, действия — в «⋯».

**Плюсы:** удобно читать код и документацию вперемешку (два-три файла под рукой); у заглушек и картинок тоже есть куда смотреть (инспектор на месте — раскладка не «прыгает»); действия подписаны и видны.
**Минусы:** самое дорогое — состояние вкладок (набор, временная вкладка, закрытие, сохранение между запусками), инспектор и две схемы на разной ширине (инспектор / строка статуса + меню); код получает 918 px вместо 1182; нужен лимит вкладок.

### Вариант 3 — «Фокус»: выдвижное дерево, палитра ⌘P, сведения в строке статуса
Сверху **одна** полоса: ≡ (дерево) · ‹ › · путь · переключатель вида · «Найти файл… ⌘P» · обновить · закрыть. Дерево — выдвижная панель (270 px, на узком окне — поверх с затемнением), в ней сворачиваемая группа «Недавние».
Поиск — **палитра по ⌘P** поверх окна: пустая — «Недавние», с запросом — результаты + «в тексте открытого файла». Оглавление markdown — **«рейка» засечек** у правого края (по наведению или фокусу раскрывается; на широком окне можно закрепить).
Внизу строка статуса: **путь** (клик копирует), тип, кодировка, строк, размер, время, переключатель «Подсветка», «Копировать путь», «Показать в Finder», «Открыть».

**Плюсы:** больше всего места под код (при свёрнутом дереве — вся ширина окна, высота +8 % к варианту 1); одна полоса вместо двух; палитра ⌘P привычна по редакторам и не зависит от ширины дерева; единая схема на любой ширине.
**Минусы:** больше всего нового поведения (палитра, выдвижное дерево, рейка); режим «Недавние» переезжает из дерева в палитру; ≡ и рейка менее заметны; действия у нижнего края, а не рядом с крошками; иконки-монограммы — отход от текущих значков.

## Рекомендация

**Вариант 1 как основа.** Он ровно соответствует плану аналитика (правая колонка только у markdown, метаданные у остальных — в строке статуса), ближе всего к текущему `DocsModal` и самый дешёвый;
для задачи «читать и смотреть все файлы» вкладки (вариант 2) и палитра (вариант 3) не обязательны — переходы по ссылкам и ‹ › уже есть. Заимствовать:
- из варианта 2 — **меню «⋯»** с «Копировать абсолютный путь» и блок «Изоляция» в сведениях HTML (в варианте 1 он уже в баннере; меню нужно на узком окне);
- из варианта 3 — **переключатель «Подсветка»** в строке статуса (если человек решит делать T6), а при желании — путь в строке статуса;
- общее для всех — иконка «поиск в файле» (линии с лупой) отличается от «поиск по проекту» (лупа): иначе рядом две одинаковые лупы.

Если важна работа с несколькими файлами сразу — вариант 2, но тогда это отдельная крупная задача (состояние вкладок).

## Открыто для решения человека

Вопросы аналитика (по умолчанию — рекомендация аналитика; макет показывает оба исхода там, где это возможно):
1. **Секреты (`.env*`, ключи).** По умолчанию — открывать как любой файл (состояние «Код» → клик по `.env`). Альтернатива — заглушка «Файл может содержать секреты» с кнопкой «Показать содержимое» (состояние «`.env` скрыт»).
2. **HTML по умолчанию.** «Код» (в макете) или «Превью»; шаблоны Vite/Next в песочнице пусты, поэтому рекомендовано «Код».
3. **PDF.** Заглушка «Открыть» (в макете) или встроенный просмотр (отдельная проверка и, вероятно, новая зависимость).
4. **Подсветка синтаксиса.** В v1 нет; переключатель «Подсветка» в макете показывает результат. Нужна ли — решает человек (новая зависимость, T6).
5. **Лимиты.** Текст 1 МиБ, картинка 10 МиБ, список 100 000 файлов — на заглушках и в баннере эти числа видны.
6. **Задачи в работе.** В макете их группа — только `.md` (рекомендация); файлы кода из worktree'ов — отдельная фича.
7. **Подмодули и вложенные репозитории** в v1 не показываются; **8. редактирования файлов нет** (в макете ни одной кнопки правки); **9. название и формат окна** оставлены прежними («Документы», модальное окно).

Вопросы по дизайну:
10. **Раскладка:** вариант 1 (рекомендуется), 2 или 3? Нужны ли вкладки открытых файлов?
11. **Иконки в дереве:** цветные по типу (1, 2) или монограммы расширения (3)? Любой вариант раскладки можно собрать с любым стилем иконок.
12. **Путь в строке статуса.** В варианте 1 путь — в крошках, в строке статуса его нет (вариант 3 показывает и там, и там). Нужен ли дубль?
13. **Пометка «изолировано, без сети»** — баннер над превью и пометка в статусе (в макете) или одного достаточно?

## Что проверено и что нет

Проверено: все три файла собраны, открыты в headless Chrome; все 19 состояний при ширине окна 1480 и 812 отрисовываются без ошибок в консоли; интерактив (клики по файлам всех типов, ⌘P / ⌘F, ↑ ↓ Enter Esc, ссылки markdown, история ‹ ›,
Код ⇄ Превью, Вписать / 100 %, закрытие ошибки, вкладки варианта 2, палитра и дерево варианта 3) прошёл автоматическую самопроверку (35 / 38 / 36 проверок); скриншоты состояний просмотрены глазами; контраст посчитан.

Не проверено: макет не открывался в самом приложении (Electron) и в изолированном фрейме показа; другие браузеры; скринридер и полноценная клавиатурная навигация по дереву стрелками (в макете её нет — в реализации
берётся `navigate` / `isTreeKey` из `fileTree.ts`); производительность на 100 000 файлов и на 1 МиБ текста (в макете файлы маленькие). Содержимое просмотров в макете — один образец на тип файла; размеры, время и счётчики выдуманы.
