# Шапка README orca-board — три варианта оформления

> Исторический материал: описание и результаты ниже относятся к моменту создания
> документа, а не к текущему состоянию приложения. Актуальное устройство —
> [общий фундамент](../../shared-foundation.md), проверки —
> [журнал готовности](../../orca-foundation-progress.md).

README отстал от v1.0.1, а у проекта нет ни логотипа, ни иконки приложения, ни скриншотов. Единственный «знак» —
кольцо с плавником, которое рисует код трея (`apps/desktop/src/main/tray.ts:49-85`, `trayIcon` и `drawIcon`). Здесь три варианта
шапки и первого экрана; текст остальных разделов в макетах — набросок, содержимое README пишет этап «Реализация».

Каждая страница `variant-*.html` имитирует рендер README на GitHub: переключатели **Тема** (светлая / тёмная / рядом) и
**Ширина** (десктоп / телефон 375), внизу — «Как шапка запишется в README.md» (разметка, которую GitHub пропустит).
Жёлтые метки 1–5 — открытые вопросы к человеку (ниже); чекбокс «пометки вопросов» их прячет.
Страницы автономны: без сети и CDN, стили inline, знаки — соседние `logo-*.svg`. Данные выдуманы, статусы бейджей условные.

| Файл | Что это |
|---|---|
| `variant-a.html` | A «Скриншот» |
| `variant-b.html` | B «Схема» |
| `variant-c.html` | C «Минимум» |
| `logo-a.svg`, `logo-a-dark.svg` | знак (кольцо с плавником) для светлой / тёмной темы GitHub |
| `logo-b.svg`, `logo-b-dark.svg` | знак в плитке + wordmark (lockup) |
| `logo-c.svg`, `logo-c-dark.svg` | wordmark без знака |

## Что общее

- **Знак** — форма иконки трея: кольцо (внешний радиус 6, внутренний 3,6, центр (8; 9) на сетке 16×16) и плавник-треугольник
  (7; 3,5) (10,5; 3,5) (8,5; 0,5). Плавник продолжен вглубь кольца по тем же рёбрам, чтобы на любом масштабе не было щели.
  Цвета — из `styles.css`: `--accent` `#7b86f5`, `--accent-2` `#5a63c8`.
  Светлая тема: градиент `#7b86f5` → `#5a63c8` (на белом 3,2:1 → 5,2:1; для графики достаточно 3:1);
  тёмная: плоский `#7b86f5` (5,9:1 на `#0d1117`).
- **Wordmark** — моно-линейные буквы из кругов той же толщины, что у кольца; дефис — акцентный. Нарисован путями, а не
  текстом: GitHub показывает SVG в `<img>` без веб-шрифтов, и шрифт «поплыл» бы у каждого читателя.
- **Светлая / тёмная тема** — пары SVG в `<picture>` с `prefers-color-scheme` (это документированный способ GitHub).
- **Только то, что переживёт GitHub.** Он вырезает `<style>` и `style=""`, поэтому всё выражено через `align`, `width`,
  `height`, таблицы, `<details>`, alert-блоки (`> [!NOTE]`) и картинки. Линия под H1 — родная у GitHub, убрать её нельзя без отказа
  от H1; поэтому в A и B заголовок стоит под знаком, а не внутри него.
- **Бейджи** в макетах нарисованы вручную; в README это shields.io (репозиторий публичный — динамические бейджи работают).
  Конкретные URL — в блоке «Как шапка запишется» каждого макета.
- **Узкая ширина.** На 375 px бейджи и навигация переносятся; в B схема переключается на вертикальную версию.

## A — «Скриншот» (`variant-a.html`)

Знак 96 px → H1 `orca-board` → однострочник «Канбан-доска для CLI-агентов: задача на доске — агент в своём git worktree.» →
4 плоских бейджа (релиз, CI, macOS | Windows, Node 24) → навигация → большой скриншот доски → «Как это работает»,
«Возможности» (таблица 3×2), «Установка», «Документация», «Лицензия».
Скриншота в репозитории нет, поэтому в hero — **заглушка-силуэт** с подписью «здесь будет скриншот доски» и пометкой
«заглушка макета, не скриншот»; это не макет интерфейса. Целевой размер — 1600 × 1000, тёмное окно без данных реальных проектов.

**Плюсы:** привычная для продуктов-приложений шапка; за секунду видно, что это доска; знак и бейджи — минимум работы
(2 SVG, готовые shields).
**Минусы:** hero зависит от файла, которого сейчас нет — до появления скриншота README выходит с дырой или с заглушкой;
скриншот 1600 px на телефоне (343 px) нечитаем, а колонки канбана выглядят как любой другой канбан; растровый файл придётся
обновлять при смене интерфейса; 4 бейджа в ряд — самая «шумная» шапка из трёх.

## B — «Схема» (`variant-b.html`)

Lockup «знак в плитке + wordmark» → «Оркестратор CLI-агентов с канбан-доской — по вашей подписке, без API-ключей.» →
3 бейджа for-the-badge (release, CI, platform) → навигация → «Как это работает»: схема
**Вы → Координатор → Доска → Воркеры в worktree → Ветка задачи** с обратной стрелкой «вопросы и ревью — за вами»,
затем то же словами (3 шага), «Установка», «Возможности», «Документация», «Лицензия».
Схема — четыре SVG: широкая и вертикальная × светлая и тёмная. В макете она одна, на CSS-переменных.

**Плюсы:** объясняет то, чего не покажет скриншот и чем orca-board отличается от «ещё одного канбана» (координатор и
git worktree на агента); сразу выносит главное отличие — подписка, без ключей; текстовый SVG, не нужен ни один растр,
всё готово к выпуску сегодня; рисунок читается на телефоне (вертикальная версия) и в обеих темах.
**Минусы:** схему надо держать в актуальном состоянии (при смене процесса — правка SVG в четырёх файлах);
переключение вертикальной версии по ширине через `<source media="(max-width: …)">` на GitHub не документировано —
проверить в превью PR; крупные бейджи for-the-badge заметно тяжелее плоских; «продукт-картинки» пока нет совсем.

## C — «Минимум» (`variant-c.html`)

Wordmark в H1 → одно предложение → сразу «Установка», затем «Как пользоваться», «Возможности» (3 строки), «Документация»,
«Лицензия». Без hero, без бейджей, без навигации: первый экран — уже инструкция.

**Плюсы:** почти нечего поддерживать; открывается мгновенно; при необходимости упрощается до обычного `# orca-board`;
без риска «дыр» и устаревания.
**Минусы:** не продаёт продукт — по шапке не понять, что это за приложение с окном и доской; нет статусов (версия, CI,
платформы), их придётся искать в Releases; для сторонних читателей выглядит как внутренний инструмент.

## Сравнение

| Объясняет идею продукта | показывает, но не объясняет | объясняет | одно предложение |
| Телефон | скриншот мелкий | отдельная вертикальная схема | лучше всех |

## Рекомендация — B

Вариант B выходит с готовыми ассетами уже сейчас и делает то, чего не сделает ни скриншот, ни минимум: за десять секунд
объясняет, чем orca-board отличается от обычной доски задач, и выносит в шапку главное отличие — работу по подписке без
ключей. Скриншот стоит добавить позже **под схемой** (в «Возможности»), когда он появится: тогда получится A внутри B
без смены шапки. Если хочется самого дешёвого пути — C, но он не помогает читателю решить «а мне это нужно?».

## Открытые вопросы (решает человек)

1. **Лицензия.** `LICENSE` в репозитории нет, `licenseInfo` на GitHub пуст. Без файла по умолчанию действуют «все права
   защищены» — форки и повторное использование юридически не разрешены. Выбрать лицензию (MIT / Apache-2.0 / своя / оставить
   закрытой); до решения бейдж лицензии не ставим, раздел «Лицензия» — заглушка.
2. **Имя.** Репозиторий `NANDIorg/BigOrcaCocks` (описание на GitHub — «Большой оркестратор коксов»), продукт — orca-board.
   Имя репозитория зашито в ссылки Releases в README, в `publish` у electron-builder (`apps/desktop/electron-builder.yml:8-11`)
   и в проверку обновлений (`docs/architecture.md`), поэтому при переименовании их придётся обновить одновременно: GitHub
   редиректит старое имя, но только пока его не занял другой репозиторий. Решить: оставить, переименовать или добавить в README пояснение «продукт orca-board».
3. **Windows.** В README сейчас: «собирается кросс-компиляцией на macOS и на живой Windows не проверялась». Как описать в
   шапке: (а) бейдж «macOS | Windows» и оговорка в «Установке» — как в макетах; (б) «Windows (beta)» в самом бейдже;
   (в) в шапке только macOS, Windows — отдельным разделом. Рекомендую (б) пока сборка не проверена на живой машине.
4. **Знак как иконка приложения.** Иконки приложения в репозитории нет (`apps/desktop/build/` без иконок). Плитка из
   lockup B — готовый набросок иконки; делать её иконкой приложения и dmg — отдельная задача (нужны `.icns`/`.ico`).
5. **README.en.md.** Нужен ли короткий английский README (интерфейс уже двуязычный, а документация — русская). Ссылка «English»
   в навигации A и B помечена; если файла не будет — убрать ссылку.

вопросов; консоль без ошибок, сетевые запросы — только сама страница и её `logo-*.svg`. **Не проверено:** реальный рендер на GitHub (`<picture>` с `media (max-width)`, shields.io, alert-блоки,

это цвет по умолчанию, у статусных бейджей его нельзя переопределить; спасает `alt` у картинки).
