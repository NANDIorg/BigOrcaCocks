# Пошаговая установка Orca Web

Установщик использует монохромный TUI. Подготовка сервера, пять этапов настройки,
автозапуск и необязательная установка CLI разделены рамками. В меню используйте
стрелки ↑/↓ и Enter; можно выбрать пункт его номером. Enter в текстовом поле принимает
предложенное значение, Ctrl+C отменяет ввод. Ширина карточек подстраивается под терминал;
`NO_COLOR=1` отключает выделение. Команда SSH в итоговой инструкции копируется целиком.

Мастер доступен начиная с Web 2.1.0. Поддерживается Linux x64, Ubuntu 24.04 с systemd.
Node 24, npm и native PTY включены в пакет; исходники, pnpm и компилятор не нужны.

```sh
curl -fL https://github.com/NANDIorg/BigOrcaCocks/releases/download/web%2Fv2.1.0/install-orca-web.sh -o install-orca-web.sh
bash install-orca-web.sh
```

## Что сделает установщик

1. Проверит окружение и предложит установить недостающие зависимости через apt.
   Из стабильных Web-выпусков выберет последний, скачает пакет и проверит SHA256.
2. При новой установке из root предложит автоматически создать обычного пользователя
   `orca`: без пароля, без копирования SSH-ключей и credentials root. Вручную создавать
   аккаунт Linux не нужно. Использование существующего пользователя требует `USE`,
   установка под root — `ROOT`. Существующая установка сохраняет своего пользователя.
3. Предложит **закрытый доступ через SSH по умолчанию** или публичный HTTPS.
   Для HTTPS нужны два свободных поддомена и подтверждение `OPEN`.
4. Объяснит каталог проектов, настроит вход в панель и отсутствующее имя/email автора Git.
   Пароль вводится скрыто, минимум 12 символов; сохраняется только scrypt hash.
5. Покажет план перед записью, настроит автозапуск и проверит приложение.
   Для поддерживаемого HTTPS настроит прокси и сертификат; при ошибке не объявит готовность.
6. Предложит установить Codex, Claude Code или оба CLI под пользователем сервиса.
   Загрузка сторонних пакетов требует `INSTALL`. В аккаунты провайдеров нужно войти самому.

Предупреждения не принимаются нажатием Enter: риск подтверждается указанным словом.
Установка обычного пользователя уменьшает последствия компрометации, закрытый доступ
ограничивает сетевую доступность. Эти меры не гарантируют отсутствие уязвимостей.

## Что такое папка Git-проектов

Это родительский каталог репозиториев. Например, внутри `/home/orca/projects` могут
лежать `site` и `bot`, каждый со своим Git-репозиторием. Это не папка установки Orca.
Можно указать существующий каталог, который пользователь сервиса может читать и изменять.

Папку можно поменять позже: запустите `orca-web configure` под пользователем сервиса,
укажите новый каталог и примените настройки. Аккаунты и профиль сохраняются, репозитории
не перемещаются. Под обычным пользователем выберите `n` для системной автонастройки
и перезапустите Orca после изменения. Для изменения HTTPS или автоматического
перезапуска повторите установщик из административного SSH-подключения, выбрав
прежнего пользователя. Системная настройка использует отдельный проверенный пакет root.
При ручной правке разрешено несколько абсолютных путей в `projectRoots` в
`~/.config/orca-web/config.json`, с последующим перезапуском сервиса.

Каталог ограничивает выбор проектов в панели. Он не является sandbox: терминал и
агенты имеют доступ ко всем файлам, доступным пользователю сервиса.

## Доступ через SSH

Домен и открытые порты не нужны. Если подключение к серверу называется `ssh my-server`,
на **своём компьютере** откройте отдельный терминал:

```sh
ssh -N -L 3737:127.0.0.1:3737 -L 3738:127.0.0.1:3738 my-server
```

Откройте `http://localhost:3737`. Туннель работает, пока терминал открыт.
Мастер может подставить пользователя, IP и нестандартный SSH-порт текущего подключения.
Alias задаётся через `ORCA_WEB_SSH_TARGET=my-server`, порт — через `ORCA_WEB_SSH_PORT`.

## HTTPS рядом с существующим сайтом

Для сайта `example.com` выделите `orca.example.com` и `preview.example.com`.
В мастере вводятся hostname без `/ru`, порта и другого пути. `https://` и завершающий
`/` принимаются и нормализуются. У своего DNS-провайдера создайте A/AAAA на IP сервера.
Установщик не запрашивает токены DNS-провайдера и не меняет записи домена за пользователя.

При публичном HTTPS любой сможет увидеть форму входа. Работа с проектами и терминалом
требует авторизации. Пароль должен быть уникальным и длинным. Регистрация посторонних
в браузере отсутствует; новый оператор добавляется только из терминала администратора.

Если сервер свободен, устанавливается Caddy из apt. При стандартном системном Caddy
добавляется отдельный файл Orca и import в `/etc/caddy/Caddyfile`; прежние сайты сохраняются.
При стандартном Nginx с include `/etc/nginx/conf.d/*.conf` добавляется только
`orca-web.conf`. Certbot получает сертификат через webroot; затем включаются HTTPS
и системное продление с проверкой и reload Nginx после обновления сертификата.
Поддерживаются IPv4/IPv6; занятые точные и wildcard-домены не перехватываются,
неоднозначные regex-конфигурации требуют ручной настройки. Перед reload выполняется
validation; при сбое возвращаются прежние файлы, origin и состояние сервисов.
Резервные копии конфигурации остаются рядом с оригиналами.
Изменённый legacy Caddyfile сохраняется; при наличии дополнительных сайтов автоматический
перенос останавливается с пояснением. Подготовленные новые блоки — `Caddyfile.generated`.

Если 80/443 заняты другим сервером или контейнером, мастер объясняет ограничение.
Выберите SSH или подключите подготовленные блоки к своему proxy вручную. DNS,
внешний firewall и нестандартные конфигурации требуют доступа к соответствующей
инфраструктуре. Завершённый HTTPS не объявляется без проверки сертификатов панели
и предпросмотра и совпадения идентификаторов работающего экземпляра.
Переход обратно на SSH требует автонастройки: публичные маршруты Orca отключаются.

## Повторная установка и CLI-агенты

При ошибке повторите тот же установщик: он продолжит настройку с сохранением аккаунтов.
`orca-web configure` меняет настройки и создаёт приватный backup текущего config.
При обновлении `UPDATE` подтверждает остановку заданий и перезапуск. Работающий вручную
экземпляр нужно сначала остановить в его терминале; чужие процессы не завершаются.
Автоматическая перенастройка работающего сервиса требует `RESTART`: задания и терминалы
будут остановлены. Отказ до применения сохраняет текущие настройки.

Установка и вход CLI доступны позже:

```sh
orca-web agents install
orca-web agents login codex
orca-web agents login claude
orca-web doctor
```

Выполняйте их под пользователем сервиса. Если установщик создал стандартного
пользователя `orca`, из root переключитесь командой `runuser -l orca`, затем выполните
нужные команды выше. `exit` вернёт в root-сессию. Codex использует device authentication для сервера без браузера.
Пароль панели Orca не заменяет подписку, ключи и вход CLI-провайдера. Доступ к Git remote
тоже настраивается под пользователем сервиса; credentials root не копируются.

Официальные способы установки: [Codex CLI](https://learn.chatgpt.com/docs/codex/cli),
[Claude Code](https://code.claude.com/docs/en/setup#install-with-npm).

Для автоматических проверок без TTY можно выбрать `ORCA_WEB_NO_SETUP=1`.
Установка под root в таком режиме требует явного `ORCA_WEB_ACK_ROOT=1`;
этот флаг не включайте для обычной интерактивной установки.
