# Orca CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans для последовательного выполнения. superpowers:subagent-driven-development допустим при отдельно выбранном пользователем режиме делегирования. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Выпустить самостоятельный чат оркестратора в терминале, используемый по SSH на Linux без Electron, с общими правилами и рабочим циклом desktop.

**Architecture:** Browser-safe core сохраняет модель и чистые переходы. Node runtime владеет состоянием, Git, диалогом ассистента и эффектами workflow; Electron и headless являются host этого runtime. `orca` открывает терминальный чат с потоковыми ответами, вопросами и реальными событиями; ассистент вызывает совместимый `orca-board`, а дополнительные подкоманды дают детерминированный доступ к тем же сервисам.

**Tech Stack:** TypeScript, Node 24, pnpm 10.33.0, node:test, текущий node-pty, JSON persistence, JSONL Unix socket, отдельная Node-сборка существующим Vite.

**Spec:** [Архитектура и матрица возможностей](../specs/2026-10-02-orca-cli-design.md).

План является предложением: реализация не начата. После уточнения пользователя основной интерфейс — интерактивный чат, а не набор команд. Диалоговый сервис и существующие structured transports ассистента входят в MVP. Полное покрытие desktop и новые drivers рабочих агентов выделены в следующие проекты в конце. Нельзя объявлять MVP полной parity.

## Global Constraints

- Рабочая основа исследования: `origin/develop`, `6275e1d`, приложение `1.1.2`; перед исполнением сверить изменения базы. Ветка `feature/*` в отдельном worktree; версии не менять вне релизного поручения.
- `packages/core` и `packages/contracts` не импортируют Node/Electron; `packages/runtime` не импортирует `apps/desktop`.
- `packages/cli/bin/orca-board.js` остаётся JS без npm/core/runtime imports и отдельно копируется в `Resources/cli`; текущие команды, ORCA-контекст, ответы и exit codes совместимы.
- Первая версия использует PTY и текущие правила запусков всех агентов. Codex допустим и как worker, и как coordinator; логин provider выполняется отдельно.
- PTY относится к рабочим агентам; чат-ассистент в MVP использует уже реализованные Codex app-server, Claude stream-json и ACP. Amp/shell остаются terminal-only по текущим capabilities.
- Provider ассистента выбирается отдельно от coordinator/developer/reviewer; переход между ними не меняет роли типа без явного поручения.
- Один источник правил/skills и один путь выполнения команды в runtime. Чат не получает отдельный workflow engine или реализацию бизнес-проверок.
- Один канонический dataDir имеет одного владельца. Lock получается до backup, миграций и конструктора TaskStore. Живой чужой socket не удаляется.
- Headless default state: `~/.orca-board/profiles/default`; короткий socket в `~/.orca-board/run/`. Desktop сохраняет старый userData. Импорт данных отдельный и только при остановленном владельце.
- `check` сохраняет consume-семантику; наблюдение не меняет `consumedBy`.
- В первой версии рестарт владельца прерывает PTY. Данные и worktree сохраняются; restart явный. Detach или конец команды клиента не останавливают агента.
- JSON stdout содержит только данные; stream — JSONL, диагностика — stderr. Новые exit codes: 0 success, 1 domain error, 2 disconnected, 3 arguments, 4 conflict/revision, 5 confirmation required, 6 incompatible protocol/capability.
- Первая проверяемая серверная платформа: Linux x64 glibc без DISPLAY. macOS desktop обязателен; остальные targets не объявлять поддержанными без smoke.
- Node/Electron native-артефакты проверяются в отдельных install/build-каталогах. Перемещение node-pty между workspace-пакетами не считается изоляцией ABI.
- Тесты — `node:test`; существующие соседние тесты переносятся вместе с кодом. Новые пакеты включают тесты подкаталогов в scripts явно. В desktop текущий glob находит только плоские `src/main/*.test.ts` и `src/renderer/src/*.test.ts`.
- Перед каждым интеграционным PR — полный `pnpm verify`; после всей задачи — локальный macOS pack и запуск по AGENTS.md. Новые команды добавлять в HELP перед документацией; изменения промптов/поведения синхронизировать со skills.

## Review Focus

1. Два старта одного профиля, alias/symlink пути, PID reuse и живой socket другого профиля: второй владелец отказывает до чтения store — задача 5.
2. Disconnect наблюдателя, backpressure и reconnect между snapshot и subscribe: события не теряются, координатор сохраняет свою очередь — задача 7.
3. Терминальный клиент погиб или вывод превысил лимит диска: PTY жив, writer lease освобождён, настройки терминала восстановлены при обычном выходе — задача 8.
4. Git-команда зависла, два проекта используют один git commonDir, ответ пришёл после перехода lane: сервис отвечает на stop/ask, операции Git сериализованы, устаревший эффект отклонён — задача 11.
5. Установка tarball вне monorepo с Node ABI, пустым PATH и отсутствующим zsh: CLI запускается, shell диагностируется/выбирается безопасно, Electron не нужен — задача 12.

Acceptance: type round-trip сохраняет workflow/roles/rules, invalid graph/revision не меняет настройки, checkout запрещён при живых worker/coordinator и занятом worktree, pull только fast-forward. ## Точки интеграции и финальная проверка

- Каждый Task — минимальная самостоятельная граница ревью; несколько связанных перенесённых файлов допустимы, если они дают один проверяемый сервис. Этап A можно интегрировать до появления нового bin.
- Нельзя одновременно менять persistence backend, граф workflow, provider transport и host lifecycle. Такие изменения разбирать следующими PR после сохранения старого поведения.
- Проверки с fake SessionHost не доказывают работу настоящего provider. Installed PTY smoke не доказывает интерактивную приёмку Codex. Эти результаты перечислять отдельно.
- Матрица desktop/CLI заполняется только реализованными операциями. Не скрывать текущие gaps формулировкой «всё из UI доступно».
- Перед передачей этапа пользователю: `pnpm verify`, нужные target smoke, просмотр diff, PR в develop, `pnpm --filter @orca-board/desktop run pack` и запуск `.app` из текущего worktree. Без merge или публикации релиза.
