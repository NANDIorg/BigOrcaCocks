# Установка Orca Web

Пользователь устанавливает Orca на Linux-сервер с существующим сайтом. Ему нужен
один понятный мастер, который объясняет параметры, выполняет доступную настройку,
требует явного подтверждения рисков и показывает проверенный результат.

## Поведение

- SSH-доступ — значение по умолчанию. Оба listener остаются на loopback. Мастер
  показывает готовую команду туннеля, включая preview, и адрес браузера.
- Для новой установки из root рекомендуется автоматически созданный обычный
  пользователь `orca`, без пароля и без копирования SSH-ключей. Установка под root
  остаётся доступной только после ввода `ROOT`. Существующую установку не переносим.
- Bootstrap устанавливает недостающие системные зависимости через apt, проверяет
  опубликованный пакет по SHA256 и сохраняет защиту путей и архивов.
- Объясняем родительский каталог Git-репозиториев, возможность изменения и то,
  что ограничение выбора проектов не является sandbox для CLI-агентов.
- Публичный HTTPS требует двух разных свободных поддоменов и подтверждения `OPEN`.
  Мастер объясняет доступность формы входа всем, необходимость сильного пароля и
  отсутствие гарантии от уязвимостей. DNS-записи пользователь создаёт у своего провайдера.
- Поддерживаем автоматическое подключение стандартных системных Caddy и Nginx.
  На свободном сервере устанавливаем Caddy из apt. Для Nginx используем Certbot webroot,
  отдельный файл Orca, проверку конфигурации, reload и откат при ошибке.
  Другие веб-серверы/контейнерные прокси обнаруживаем и объясняем следующий шаг;
  существующий сайт не перехватываем и успешный HTTPS не объявляем без проверки.
- Установка systemd, updater и локальная health-проверка автоматические, когда
  доступны административные права и systemd. Подтверждение общего плана — до записи.
- Повторная настройка сохраняет аккаунты и профиль, создаёт резервную копию config.
  Новый `orca-web configure` запускает мастер для существующей установки.
- Пароли вводятся скрыто и не попадают в argv/env/журнал. Пакет и привилегированный
  provision выполняются из проверенного root-owned временного каталога; код обычного
  пользователя не запускается с root-правами.

## Проверка

Тестируем подтверждения/отказ без записи, валидацию доменов, сохранение аккаунтов,
повторную установку, шаблоны Nginx/Caddy, конфликты и откат. Linux smoke использует
настоящий пакет, TTY, Node/PTY, два аккаунта и перезапуск; systemctl в контейнере
проверяем на границе, DNS/публичные сертификаты отмечаем отдельно.

## Выпуск

Совместимые новые возможности относятся к Web 2.1.0. Desktop не переупаковываем.
Проходим PR/CI и отдельный Web release workflow, выполняем приёмку архива и
синхронизацию master обратно в develop. Полномочия публикации определяются поручением
и `docs/releasing.md`, существующие теги и бинарные ассеты не изменяются.
