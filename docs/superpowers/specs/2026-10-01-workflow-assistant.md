# Создание и редактирование воркфлоу через ассистента

Пользователь обсуждает процесс в существующем чате ассистента. Ассистент создаёт новый тип задачи с готовым графом либо меняет граф выбранного типа. Ручное перетаскивание нод не требуется; результат открывается в обычном редакторе.

## Сценарии

- Предложение создания в приветствии и «Создать с ассистентом» в меню нового типа заполняют поле одинаковым локализованным текстом без отправки и чипа создания. Меню открывает чат без создания пустого типа; одноразовый nonce-запрос не перезаписывает последующие правки при повторном открытии.
- Во вкладке воркфлоу есть действие изменения с ассистентом. В чат передаётся текущий корневой черновик, включая вложенные пути, исходный сохранённый граф и выбранный путь. Передача не сохраняет черновик и не отправляет сообщение автоматически.
- Конкретный контекст и возврат показаны только после явной передачи из редактора; текст пользователя сохраняется. Снятие чипа, обычное открытие через rail/сочетание и новый диалог очищают вложение, возврат и ожидающий выбор агента. Принятая отправка снимает только вложение, оставляя возврат во время редакторной дискуссии.
- Ассистент обсуждает недостающие требования, читает схему и роли, проверяет граф и сохраняет его, когда пользователь поручает создание или изменение. Обсуждение без поручения не меняет библиотеку.
- После сохранения в чате появляется действие открытия полученного типа во вкладке воркфлоу.
- Сценарий работает без выбранного проекта: библиотека типов общая для приложения.

## Контракты

Socket/CLI: `workflow schema`, `workflow get --type <id>`, `workflow validate --type <id> --definition '<JSON>'`, `workflow set --type <id> --revision <token> --definition '<JSON>'`, `workflow create --title <title> [--base-type <id>] --definition '<JSON>'`. Для create используются роли базового типа или стандартные роли; validate поддерживает тот же выбор через `--base-type`, а `--type` необязателен для проверки нового графа. `--file` — альтернативный источник JSON. `types list --all` перечисляет библиотеку. Существующий `workflow show` сохраняет своё назначение.

`get` возвращает полный эффективный граф, безопасные роли без приватных флагов запуска, название, признак пользовательского графа и ревизию всего сохранённого типа. `validate` не пишет состояние и возвращает подготовленный граф, ошибки и предупреждения. `set` требует актуальную ревизию и меняет только workflow. `create` валидирует до вставки, возвращает новый id и не запускает задачи. Нет доступа к произвольным настройкам через новые команды.

Подготовка проверяет форму сырого JSON рекурсивно до семантического валидатора. Недостающие координаты получают общую автоматическую раскладку; существующие координаты и id сохраняются. Условные, параллельные и вложенные графы используют действующую модель core.

Новый отдельный метод IPC `assistantChat.sendWithWorkflow` делает поддержку контекста обнаружимой. Main формирует контекст по сохранённому типу, проверяет исходный граф и снабжает его ревизией. Данные черновика передаются модели один раз после успешной отправки, но не выводятся как технический JSON в сообщении пользователя. Дальнейшие реплики продолжают обсуждение без повторной отправки устаревшей базы. Ошибка отправки сохраняет контекст; новый диалог явно снимает вложение и возврат. Backend create-контекст сохраняется для старых клиентов; обычное создание идёт текстом с уже доступным workflow skill. Обычный send остаётся совместимым. Событие `workflowAssistant:saved` содержит только id, название и ревизию успешного сохранения для кнопки результата.

Сохранение графа редактором использует узкий IPC `workflowAssistant.save(typeId, baseline, workflow|null)` с атомарной проверкой исходного эффективного графа. Обычные патчи настроек типа и переименование используют main-операции над последним сохранённым типом, чтобы отложенное автосохранение другой вкладки не заменило свежий граф старым. Новые методы обнаруживаются в старом preload и показывают сообщение о перезапуске вместо небезопасной замены целого типа.

## Защита данных и границы

Изменение библиотечного типа действует в проектах, использующих его; существующие прогоны сохраняют снимки графов. Роли, разрешения, модели и правила сохраняются. Проверка ревизии и запись выполняются без асинхронного разрыва. Удалённый тип не восстанавливается. Ошибки не меняют память или диск.

Чистый черновик редактора принимает внешнее обновление. Грязный сохраняется с сообщением о конфликте; сохранение прежнего черновика не может молча заменить новый граф. Возврат из чата также сохраняет исходную базу. Открытие результата явно выбирает сохранённый граф.

Тексты ru/en, существующие контролы и темы, IME и фокус чата, сообщение о необходимости перезапуска старого main/preload. Без новых зависимостей, миграции формата хранения и отдельного модельного транспорта.

## Проверка

Поведенческие тесты CLI, socket, ProjectManager, core и чистых функций синхронизации/контекста; проверки транспортов скрытого контекста. Полный `pnpm verify`, локальная сборка и запуск. Ручную проверку интерфейса выполняет пользователь.
